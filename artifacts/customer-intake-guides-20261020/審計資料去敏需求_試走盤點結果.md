# 審計資料去敏需求盤點結果

日期：2026-10-20  
版本：1.0  
用途：供未來客戶使用指引參考的已填寫範例。  
依據：本次會計事務所角色扮演的口述回答，尚未核對實際公司檔案。

這份文件示範如何先確認資料與需求，再討論去敏規則。範例答案不代表其他公司的現況，也不代表目前網頁已支援以下所有需求。

## 1. 處理哪些資料

| 項目 | 本次確認內容 |
|---|---|
| 收到的資料格式 | Excel、CSV |
| 本次盤點範圍 | Excel |
| 資料名稱 | 審計資料 |
| 來源與整理方式 | 原始來源不一，由經手人整理成公司統一版本 |
| 處理對象 | 整理後、公司統一版本的審計資料 |
| 預計用途 | 去敏後供 AI 協助合併資料、審計與檢查 |
| 尚未涵蓋 | CSV 的實際欄位與處理需求 |

## 2. 哪些去敏、哪些保留

| 欄位／內容 | 已確認的需求 | 待確認事項 |
|---|---|---|
| 客戶名稱／公司名稱 | 去敏 | 具體替代方式 |
| 人員資料 | 去敏，包含備註中的人員資料 | 除備註外，是否出現在其他欄位；具體替代方式 |
| 統編 | 去敏 | 具體替代方式及與客戶的對照方式 |
| 憑證號碼 | 必須能對照 | 保留原號或改用代號，尚未決定 |
| 日期 | 保留 | 尚未核對實際格式 |
| 金額 | 保留 | 尚未核對實際格式 |
| 稅額 | 保留 | 尚未核對實際格式 |
| 會計科目 | 保留 | 尚未核對實際格式 |
| 備註 | 其中的公司名稱、人員資料要去敏 | 其餘內容如何處理，待核對樣本 |

人員資料是使用者指定的內容類型，尚未確認是否有獨立同名欄位。不得因未列出其他敏感內容，就推定其不存在。

## 3. 格式與對照要求

使用者明確要求：

- 保留原欄名。
- 保留欄位順序。
- 保留列位置。
- 同一客戶在不同檔案裡仍能對照。
- 同一憑證在不同檔案裡仍能對照。

目的：方便繼續工作及人工檢查，讓原檔與去敏副本能逐欄、逐列比較。

引導者解讀：去敏階段不能擅自改欄名、排序、合併或刪除資料列。跨檔對照屬於需求，尚未決定代號或比對機制。

## 後續待確認

1. 客戶、統編及憑證的對照方式；若採代號，哪些欄位需要共用對照關係。
2. 人員資料除了備註，是否也出現在其他欄位。
3. 實際 Excel 是否有公式、多工作表或特殊排版需要保留。
4. CSV 的實際欄位與處理需求，另行盤點。

引導者建議：在本機選一份具代表性的 Excel，依本表逐欄核對，補齊會影響去敏決定的缺口後，再討論範例網頁的調整。不要將真實客戶資料貼入訪談對話。

## 未來提供給客戶時怎麼使用

搭配同資料夾的 [三個重點引導稿](去敏需求盤點_逐題引導稿.md)，由引導者一次問一個重點：

1. 檔案有哪些欄位或內容？
2. 哪些一定要去敏、哪些必須保留？
3. 去敏後需要維持什麼格式與對照關係？

沿用客戶已回答的背景，不重問；由引導者整理答案，最後交付 Markdown 結果讓客戶更正。不要直接要求客戶填大型 Excel 表格，也不要把這份範例的欄位與規則當成其他公司的預設答案。

引導稿中的「已回答的內容」屬於本次試走；用於新客戶時，應換成該客戶實際提供的背景。未提供的內容記為待確認。

本文件是需求盤點範例，不是網頁功能說明或操作驗收結果。未來正式操作指引需依接手專案的實際介面與已驗證能力撰寫。本次未修改網頁、未執行真實資料去敏，也未授權資料外送、匯入 E 或上傳 GitHub。
