# 會計事務所每週進項憑證：合成資料與去敏規則 v1.0

## 本工作副本新增：精簡 AI 結果匯入與還原

新版入口仍為本目錄的 `會計憑證本機去敏.html`。原交接快照與原始來源保留在原位置，本工作副本用既有 3 份合成 CSV 測試。

1. 載入合成案例或 CSV，執行去敏。
2. 按「儲存去敏資料」及「儲存還原檔」。原檔可另下載，ZIP 內保留讀入時的原始位元組。
3. AI 可合併、刪改、新增、重排列與欄位。AI 專用 CSV 右側附「批次編號」；回傳每列必須保留相同值，以及完整公司、人員、憑證等代號。
4. 匯入 AI 結果 CSV 與同批對照表，按「還原資料」。欄名若是代號（例如樞紐彙總），也會還原。完成後下載新 CSV。

還原只依完整代號取回原值，不要求原列數或列位置；AI 計算值、科目修改及新備註保持。多對象儲存格保留多個代號，還原成多個原值。未知或被改壞的可辨識代號、待覆核標記保持原樣並列出提醒；刪掉代號後無法猜回對象。批次錯誤則停止還原。

對照表與還原結果含原值，只留本機。先前交接包的舊版陣列代號表不帶批次；本版還原請使用本版儲存的還原檔，或下方試用對照表。

執行 `node test-restore.cjs` 後，可在本機試用 `runs/restore-test/PRIVATE/identity_map.json` 搭配 `runs/restore-test/ai_result.csv`。此結果是本機模擬 AI 計算：28 筆一般帳務經合併、刪改、重排及新增彙總後為 25 筆；健康、私人 2 筆未放入 AI 專用輸入。`restored_result.csv` 是預期結果，`ai_result_warnings.csv` 可試未知代號與不可反推的備註標記。

實際驗證見 `runs/restore-test/validation.json`（核心與合成案例）、`ui-validation.json`（打包 HTML 的 DOM 操作模擬）與 `runs/verified/validation.json`（既有去敏回歸）。未呼叫外部 AI，未執行原生 Chrome 驗收。

維護時可用 `node package.mjs` 只重新打包 HTML，不重新產生合成原檔。`build.mjs` 是舊有合成資料生成器，仍會重寫合成原檔；一般改介面請用 `package.mjs`。測試命令為 `node test.cjs`、`node test-restore.cjs`、`node test-ui.cjs`，輸出均位於本工作副本的 `runs/`。

本版讓事務所測試「收件、比對、查重、補件」能否在去敏後繼續完成。保留原檔名、原欄名、欄位順序與每筆資料的列位置；不自動刪除重複列、不更正金額、不重分類科目。

這是本機覆核試作。金額、日期、檔名仍可能涉及客戶機密；代碼化不等於不可回推的匿名化。本批未連接外部 AI；共享版本只包含程式、文件與合成範例，不含本機產生的還原檔。

## 直接試用

1. 用 Chrome 開啟本資料夾的 [會計憑證本機去敏.html](會計憑證本機去敏.html)。
2. 按「用範例試試」→「產生去敏資料」。
3. 按「儲存去敏資料」及「儲存還原檔」，將兩份檔案放在同一個資料夾。還原檔含原值，留在本機。
4. 將去敏資料解壓縮，把資料及操作說明交給 AI，保留完整代號及批次編號。
5. 選擇同批還原檔與 AI 結果，按「還原資料」，確認後「儲存還原結果」。

開啟網頁試用不需執行 Python、PowerShell 或安裝套件。合成原始檔位於 `synthetic_originals/`；可用網頁的「另存原始檔案」保存副本。測試輸出與還原對照資料由測試在本機產生，不隨共享版本上傳。

## 模擬的實際工作

假設事務所每週收到不同客戶、窗口或補件管道的進項憑證清冊，先核對資料品質，再決定如何補件與入帳。

- 3 個虛構客戶、5 個虛構供應商；客戶異名另列為識別衝突，不自動視為同名。
- 3 份 CSV、每份 10 筆、25 欄；第二份刻意使用不同欄名及順序。
- 28 筆一般帳務，另有健康、私人各 1 筆，用於測試排除。
- 未稅金額、稅額、總額、科目、附件、付款狀態、折讓與原憑證關係都有具體內容。
- 包含 TWD、USD、零金額、缺值、負數折讓、收據與免稅標記，不能把空白當成 0。
- 身分與帳號刻意使用 `SYN-`、Email 使用 `example.invalid`。這些是假資料識別符，不能通過正式統編、帳號、發票驗證；真實感來自工作情境及關係，而非模仿可用的私人識別碼。
- 台幣一般應稅樣本以整數稅額生成；此生成慣例不作為通用稅額判定規則。檢查器只核對提供的未稅＋稅額＝總額，不一律強套 5%。

## 資料欄位與去敏處理

| 欄位群 | 本版處理 | 保留的能力 |
|---|---|---|
| 客戶名稱、客戶統編、供應商名稱、供應商統編 | 每一個相同原值在同批使用相同代號；名稱與統編分別編碼 | 比對相同交易對象；名稱與統編不一致仍能發現 |
| 聯絡人、電話、Email、銀行帳號 | 用人員、電話、信箱、帳戶代號取代完整值；空白保留 | 在同批辨識相同聯絡窗口，不把可聯絡資料交給後續處理者 |
| 憑證號碼、原憑證號碼 | 以客戶識別、供應商識別、年份與號碼建立關聯代號 | 同號查重、跨檔補件與折讓引用；不同買方同號不誤合併 |
| 憑證日期、收件日期、入帳月份、原憑證日期 | 有效日期／月份原樣保留；格式不適用則留待覆核提示 | 跨期、收件日異常、折讓原單日期比對 |
| 未稅金額、稅額、含稅金額 | 原字串保留；精確十進位計算，不用浮點數核對；不自動修正 | 加總不符、同號金額衝突、負數及缺漏 |
| 憑證類型、會計科目、幣別、課稅別、附件、付款狀態 | 已核定詞彙保留；空白保留；未知詞彙只留本機待核 | 分類、缺科目、補件及待確認狀態 |
| 備註 | 先替換本批宣告的公司／聯絡識別；剩餘整段必須全由允許業務詞彙和標點組成 | 保留「驗收單待補」「科目待確認」「請聯絡人員-001」等意義 |
| 健康、私人或未知資料分類 | 整列內容只留本機；副本該列保留位置與「本列僅限本機」標記 | 人工可定位原列，私人內容不出現在覆核副本 |

不是讓各欄都變成 `[已遮蔽]`。例如：

| 欄位 | 合成原值 | 去敏稿 |
|---|---|---|
| 客戶名稱 | 合成青禾設計有限公司 | 公司-001 |
| 憑證號碼 | SYN-INV-0001 | 憑證-001 |
| 憑證日期 | 2026-10-01 | 2026-10-01 |
| 未稅金額 | 12500 | 12500 |
| 稅額 | 625 | 625 |
| 含稅金額 | 13125 | 13125 |
| 付款狀態 | 已付款 | 已付款 |
| 備註 | 例行月結；請聯絡虛構林會計 | 例行月結；請聯絡人員-001 |

本批 28 筆一般帳務中，僅 1 筆備註因含未宣告的聯絡窗口與分機而變成 `[備註待人工覆核]`；其餘帳務欄位仍可核對。這是讓人工補足規則的例外，不宣稱正規表示式能理解任意備註。

## 可以立即核對的情境

以下列號包含表頭，指 CSV 邏輯列；同一格內換行不另算一列。

| 原檔／列 | 刻意放入的情境 | 去敏後應有結果與人工動作 |
|---|---|---|
| 第一批第 2、11 列；補件批第 2 列 | 同一憑證多次收到 | 仍是同一憑證代號；列重複候選，人工選有效版本 |
| 第一批第 4 列；補件批第 3 列 | 同一憑證 48000／48100，且缺科目 | 顯示金額衝突、缺科目；不可擅自取最新或加總 |
| 第一批第 3、8 列；補件批第 5 列 | 缺發票影本、驗收單或付款證明 | 各自保留缺件原因，交給窗口補件 |
| 第一批第 5 列 | 3600＋180 與總額 3781 不符 | 留下原值並列帳務待辦 |
| 第一批第 6 列 | 9 月憑證於 10 月入帳 | 提醒跨期，是否合理由會計確認 |
| 第一批第 9 列 | 稅額與總額空白 | 仍空白，列缺漏；不能當成 0 |
| 第一批第 10 列 | USD 128.75 | 保留原幣與小數，不與 TWD 混算 |
| 補件批第 4、6 列 | 折讓 -1600／-80／-1680 指向原單 | 引用與原單代號一致；另核對日期及幣別 |
| 補件批第 8 列 | 未宣告的聯絡人及分機混入備註 | 備註原文僅存本機，主稿提示人工覆核 |
| 補件批第 9 列 | 折讓原單不在本批 | 提醒找原單，不能推論原單不存在 |
| 補件批第 11 列及同客戶其他列 | 同統編、客戶名稱多一個採購部尾註 | 列身分對應衝突，不靜默合併 |
| 第二批第 2 列 | 與第一批同憑證號，但買方不同 | 不判為同一張重複憑證 |
| 第二批第 3 列 | 折讓缺原單號與日期 | 留下折讓金額，列關聯待補 |
| 第二批第 4 列 | 收件日早於憑證日 | 列日期待確認 |
| 第二批第 5 列 | 未稅、稅額與總額都是 0 | 原樣保留，與缺值分開 |
| 第二批第 7、8 列 | 超出本次月份、非折讓卻是負數 | 分開提醒，不自動改帳 |
| 第二批第 10、11 列 | 健康、私人資料 | 只留列位置，原文不進主輸出 |

## 規則與來源分開

**官方來源內容：** 財政部電子發票文件的欄位包含買賣方、發票號碼、開立日期、銷售額、稅額與總額，可作為本案例欄位設計的依據。參考 [官方發票欄位檢核說明](https://www.einvoice.nat.gov.tw/static/ptl/ein_upload/download/5440.pdf) 與 [MIG 4.1 A0101 訊息結構](https://www.einvoice.nat.gov.tw/static/ptl/ein_upload/download/5380.pdf)，查閱日 2026-10-20。本工具沒有實作或宣稱符合完整 MIG 規格，也未宣稱這些版本就是所有情境的最新規範。

**本案建議：** 每週收件欄位、資料分類、科目白名單、代號格式、備註允許詞彙、重複候選鍵、折讓負數慣例與提醒條件，都是本次最小試點設計，不是法定規則。折讓用負數只表示本清冊的沖減慣例，不是電子發票訊息格式要求。跨期或缺件只表示待確認，不能直接斷定不可入帳或不可扣抵。

**待事務所確認：** 實際檔案格式、科目表、幣別精度、同單號的唯一性、折讓正負號慣例、名稱別名對照、客戶是否同意保留精確日期與金額給特定 AI 處理者、備註可保留詞彙，以及人工覆核負責人。未確認前只用合成資料試跑。

## 驗證與限制

- 3 份、30 筆、25 欄；原檔名、欄名、順序、列位置與原有空白皆通過比對。
- 28 筆一般帳務的有效日期、精確金額、稅額、科目、狀態均保持不變。
- 用去敏 CSV 重新計算，得到與原始 CSV 完全一致的 **29 項業務提醒**；這是提醒數，不是 29 筆不同錯誤憑證。
- 3 項隱私提醒：1 筆未知備註、2 筆本機專用列。
- 15 組程式檢查通過，包含已知識別字串未殘留、跨檔同碼、折讓引用、公式文字攔截、日期欄誤填識別數字、偽裝代號的備註、CSV 引號與換行，以及網頁 DOM 事件模擬。證據見 [validation.json](runs/verified/validation.json)。
- 獨立審查曾發現日期欄純數字、偽裝代號備註、折讓原日期不符三項缺口，已補上針對性回歸檢查。
- 原生 Chrome 的實際畫面與下載操作尚未完成自動驗收；DOM 模擬不等於原生瀏覽器驗收。
- 支援 UTF-8 CSV，25 個已知欄位及所列別名；單批最多 20 檔、每檔 1 MB、合計 10 MB、20,000 筆。未知／重複／缺少欄位或重複檔名會停止整批。
- 輸出 CSV 統一為 UTF-8 BOM、CRLF。保留欄名、欄序、列與欄值；不承諾保留原始引號樣式、檔案時間、原位元組格式。CSV 本身不儲存 Excel 字型、色彩、欄寬或公式格式。
- 目前只在同批維持代號一致；不同批次或選檔順序可能換碼。跨週追蹤應另建受控且僅限本機的代號庫，不把對照表交給 AI。
- 原檔名有客戶名稱時，保留檔名的覆核 ZIP 也會包含該名稱。輸出明確要求檔名及精確數值人工覆核，不能直接當成可外傳包。
- 任意數字若誤填在金額欄，可能仍符合金額格式；程式不能據此保證無個資。需要事務所確認欄位用途與數值合理性。
- 尚不含影像 OCR、附件內容掃描、薪資、員工身分證、完整總帳／試算表勾稽、匯率換算、申報或扣抵判斷。其他任務需要不同的最小必要欄位與規則。

## 如何衡量這個試點

先由人工核對同一批合成資料建立基準，再跑去敏及整理流程。記錄整理時間、人工覆核時間、應找出的問題命中數、漏報數、誤報數、需追查原檔的次數，以及不必要遮除的格數。分開評估「去敏是否保護資料」及「去敏後是否仍能做原本的工作」，不把代號數量當作成功指標。

本批只有程式正確性與合成情境驗證，尚無真人計時或真實客戶資料測試，因此沒有宣稱省下多少工時或達到零洩漏。
